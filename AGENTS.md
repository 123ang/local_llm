## Shared project context

Claude Code, Codex and OpenClaw all follow this file.

- Before answering questions or changing anything, read `PROJECT_BRIEF.md` (where the project stands) and the top of `CHANGELOG.md` (recent history), then check current Git, source and runtime. If they disagree, say so.
- Keep implemented, deployed, planned and unverified apart. A commit is not a deploy, and source is not a passing test.
- After authorized work, add a `CHANGELOG.md` entry under today's date in the same commit. If the project's status changed, update `PROJECT_BRIEF.md` too, with the date and the evidence or checks actually run.
- Project rules go in this file, not in `CLAUDE.md` or an assistant's personal memory.
- Existing project rules still apply. This is not permission to deploy or change scope.
